# ADR-0002. Хранение в JSON с атомарной записью

## Контекст и постановка задачи

Где и как хранить настройки, оригинал адаптера и результаты, чтобы оригинал не терялся при сбое питания и данные версии на C# читались без конвертации? (REQ-REL-002, REQ-INST-002)

## Драйверы решения

* сохранность оригинала при аварийном завершении
* совместимость с %LOCALAPPDATA%\WebShiftDnsSwitcher
* отсутствие внешних библиотек

## Рассмотренные варианты

* JSON-файлы и QSaveFile
* QSettings (реестр)
* SQLite через QtSql

## Итог решения

Выбранный вариант: «JSON-файлы и QSaveFile», потому что формат совпадает с версией на C#, а запись через временный файл и переименование не оставляет повреждённый файл.

### Последствия

* Хорошо: данные прежней версии читаются без миграции
* Хорошо: файлы можно открыть и проверить вручную
* Плохо: нет транзакций между файлами — порядок записи задаётся кодом Engine

### Подтверждение

Тест storage в self-test: принудительное завершение после записи состояния, затем restore.

## Плюсы и минусы вариантов

### JSON-файлы и QSaveFile

* Хорошо, потому что формат совпадает с версией на C#
* Хорошо, потому что атомарная запись QSaveFile
* Нейтрально: нет связей между файлами

### QSettings (реестр)

* Хорошо, потому что встроено в Qt
* Плохо, потому что данные прежней версии в JSON не читаются
* Плохо, потому что реестр не переносится вместе с данными

### SQLite через QtSql

* Хорошо, потому что есть транзакции
* Плохо, потому что нужна миграция данных версии на C#
* Плохо, потому что данных мало (единицы килобайт), СУБД избыточна
